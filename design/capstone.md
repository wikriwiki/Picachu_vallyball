# 인생게임 온라인

## 핵심 문장
"클라이언트"는 "서버"의 방에 접속해 조작을 보내고, "룰 엔진"이 "게임 데이터"로 판정한 상태를 받아 "3D 화면"에 그린다.

- 분해 축: 역할(role-of). 코드가 실행되는 위치와 책임으로 나눈다.

## 주요 기능
- 방 만들기·참가: 4자리 방 코드와 초대 링크, 최대 4명, 빈자리는 CPU (서버, 클라이언트)
- 끊김 대응: 같은 탭 자동 재접속, 끊긴 플레이어의 차례는 몇 초 뒤 자동 진행 (서버, 클라이언트)
- 룰렛 조작: SPIN 버튼(또는 스페이스바)을 누르고 있다가 떼면 룰렛이 돈다 (클라이언트, 3D 화면)
- 인생 진행: 7개 시대, 갈림길, 칸 효과, 능력치·운세, 동아리·진로·직업, 연애·결혼·자녀, 여행 서브맵, 카드, 약속어음 (룰 엔진, 게임 데이터)
- 게임 모드 3종: 인생 모드, 어른 모드, 어린이 모드 (룰 엔진, 게임 데이터)
- 결과 발표: 현금·보물·집·자녀·골 순위·특별상·약속어음을 합산한 순위 (룰 엔진, 클라이언트)
- 3D 보드 연출: 툰 셰이딩 월드, 보드 칸, 말 이동, 3D 룰렛, 이벤트 연출 (3D 화면)
- 배포: Render 무료 배포, cloudflared 터널로 접속 가능 (서버)

## 전역 제약
- 언어/런타임: TypeScript 5 (strict), Node.js 20 이상, ES 모듈
- 플랫폼: 데스크톱·모바일 웹 브라우저 클라이언트 + Node.js 서버 한 개 (HTTP 정적 파일 + WebSocket)
- 라이브러리: 3D 는 `three`, 실시간 통신은 `ws`. 그 외 런타임 의존성은 추가 전에 설계에 적는다.
- 빌드 [제안]: 클라이언트는 Vite 로 번들, 서버는 `tsx` 로 실행하고 `tsc` 로 타입 검사
- 코드 위치 규약: 설계 경로를 그대로 따른다. `design/a/b/b.md` → `src/a/b/b.ts`. 테스트는 같은 폴더의 `b.test.ts`. 예외: Vite 진입 HTML 은 프로젝트 루트 `index.html` 이며, 이 파일은 클라이언트의 화면 골격 leaf 가 정의한다. 설정 파일(`package.json`, `tsconfig.json`, `vite.config.ts`, `vitest.config.ts`, `render.yaml`)은 이 capstone 이 근거다.
- 테스트 도구 [제안]: Vitest (DOM 이 필요한 테스트는 jsdom 환경). E2E 는 Playwright
- 개발 실행: `npm run dev` = 서버(tsx, 포트 3000) + Vite 개발 서버(포트 5173, `/ws` 를 3000 으로 프록시). 배포: `npm run build` 후 `npm start` 가 빌드된 클라이언트(`dist/client`)를 제공한다.
- 결정성: 룰 엔진은 순수 함수이며, 난수는 시드를 받은 난수 생성기로만 만든다. 같은 시드와 같은 조작 순서면 결과가 같다.
- 서버 권위: 게임 상태의 판정은 서버에서 룰 엔진으로만 한다. 클라이언트는 받은 상태를 보여 주고 조작만 보낸다.
- 금액 단위: 만원 단위 정수
- 기존 코드: `public/`, `server/`, `shared/`, `test/` 의 기존 JavaScript 는 참고 자료일 뿐이다. 새 코드는 `src/` 에 새로 작성하고, capstone 통합이 끝나면 기존 코드를 삭제한다.
- 기존 규칙 문서: `docs/ADR.md` 의 규칙과 수치는 해당 leaf MD 로 옮긴다. 모두 옮기면 ADR 을 삭제한다. 원작과 다른 추정 수치는 leaf 에 `[추정]` 으로 표시한다.

## 자식 구성요소
| 구성요소 | 한 줄 설명 | 설계 파일 |
|---|---|---|
| 클라이언트 | 브라우저 앱: 로비·HUD 같은 2D UI, 입력, 서버 연결과 재접속 | [client.md](client/client.md) |
| 서버 | 정적 파일 제공, WebSocket 방 관리, 턴 진행, CPU·오프라인 자동 진행, 통신 규약 | [server.md](server/server.md) |
| 룰 엔진 | 게임 상태와 조작을 받아 다음 상태와 이벤트를 판정하는 순수 함수 모음 | [engine.md](engine/engine.md) |
| 게임 데이터 | 시대·직업·카드·칸·보드 배치 등 규칙이 참조하는 읽기 전용 데이터 | [data.md](data/data.md) |
| 3D 화면 | 게임 상태를 3D 월드·보드·말·룰렛으로 그리고 이벤트를 연출 | [view.md](view/view.md) |

## 통합 방식
- 진입점 두 개
  - 서버: `src/server/main.ts`. HTTP 서버를 열고 빌드된 클라이언트 파일을 제공하며, WebSocket 연결을 서버의 방 관리에 넘긴다.
  - 클라이언트: `src/client/main.ts` (`index.html` 에서 로드). 로비 UI 를 띄우고, 서버에 연결하며, 게임이 시작되면 3D 화면을 만든다.
- 초기화 순서: 게임 데이터 → 룰 엔진(데이터를 받음) → 서버(룰 엔진을 받음) / 클라이언트 → 3D 화면(데이터를 받음)
- 자식에게 요구하는 것
  - 게임 데이터: 읽기 전용 데이터, 시드로 보드 배치를 만드는 결정적 함수, 그리고 여러 자식이 함께 쓰는 공용 헬퍼(시드 난수 생성기, 금액 표기)를 공개한다. 다른 자식에 의존하지 않는다.
  - 룰 엔진: 게임 생성, 조작 적용(다음 상태 + 연출용 이벤트 목록), 가능한 조작 목록, CPU 조작 선택을 순수 함수로 공개한다. 상태는 JSON 으로 직렬화할 수 있어야 한다. 게임 데이터만 참조한다.
  - 서버: 방 생성·참가·시작, 턴 타이머, CPU·끊긴 플레이어 자동 진행, 상태·이벤트 방송을 맡는다. 클라이언트와 주고받는 메시지 형식(통신 규약)을 정의해 공개한다.
  - 클라이언트: 서버의 통신 규약으로 조작을 보내고 상태·이벤트를 받는다. 받은 이벤트는 3D 화면에 연출을 맡기고, 끝나면 HUD 를 갱신한다.
  - 3D 화면: 캔버스와 게임 데이터로 만들어지고, 상태를 그리는 기능과 이벤트를 연출하는 기능(끝날 때를 알림)을 공개한다. 룰렛 연출도 여기서 한다. 규칙 판정은 하지 않는다.
- 데이터 흐름: 클라이언트 입력 → WebSocket → 서버 → 룰 엔진 조작 적용 → 새 상태 + 이벤트 → 방의 모든 클라이언트에 방송 → 3D 화면 연출 → HUD 갱신

## 수용 기준
- 브라우저 두 개로 한 명은 방을 만들고 한 명은 코드로 참가해 CPU 두 명을 추가하고 시작하면, 게임이 끝까지 진행되고 결과 발표에 네 명의 순위가 나온다.
- 게임 도중 한 플레이어의 연결을 끊었다가 같은 탭으로 돌아오면 진행 중인 상태가 그대로 보인다. 끊긴 동안 그 플레이어의 차례는 자동으로 진행된다.
- 같은 시드와 같은 조작 순서로 두 번 진행하면 최종 상태가 같다.
- 세 모드 각각 CPU 만으로 60판씩(총 180판) 진행하면 모두 오류 없이 결과 발표까지 끝난다.
- 모바일 폭(375px) 화면에서도 로비, SPIN, 선택지 조작이 가능하다.
